## 🎬 起因

这一两年最唬人的一句话是「一句话出视频」：给 AI 一句需求，它写出帧精确的动画代码，然后渲成 MP4。我一直想验证它到底有几分真——于是挑了一首反复听的歌，张叶蕾《还是分开（Acoustic Version）》，让 AI 把它做成一支 MV。

先给结论：3 分 49 秒，1080×1920 竖屏，6875 帧，一个 106MB 的 MP4。从建工作区到拿到成片，前后约十个小时，其中真正写代码的时间不到两小时。

剩下八个小时，我几乎全花在一件事上：**把成片拆成一帧一帧，看它到底长什么样。**

## 🧠 心法只有一句：一帧 = 一个纯函数

```tsx
const frame = useCurrentFrame();
const opacity = interpolate(frame, [0, 30], [0, 1]);
return <AbsoluteFill style={{ opacity }}>你好</AbsoluteFill>;
```

30fps 的 15 秒 = 450 帧。没有时间轴面板，没有关键帧，没有曲线编辑器，只有「帧号 → 数值」的映射。

这件事的真正意义在于：它和 Sora / 可灵那类生成式视频是两条路。那边是**猜**像素，这边是**算**像素。渲染的时候模型根本不在场——headless Chrome 把每一帧截下来，ffmpeg 编码成 MP4。所以文字永远不会糊，图形永远不会漂，同一份代码渲一百遍，结果字节级一样。

> 这不是「AI 生成视频」，这是「AI 写了一段生产视频的程序」。前者每次都不一样，后者每次都一样。

## 🛠 真实的流水线

技术路线固定为 Remotion（React → 视频），六步：

```bash
npx create-video@latest                  # 1. 起工程（Blank + TypeScript）
npx skills add remotion-dev/skills       # 2. 装官方 12 个 skill（别跳过，见下）
# 3. 写 brief：主题 / 时长 / 画幅 / 分镜表 / 文案 / 配色
# 4. 写 composition：Scene1..N 用 <Series> 串起来
npx remotion studio                      # 5. 预览（必需，不是可选）
npx remotion render StillApartMV out/mv.mp4 --concurrency=6 --crf=17   # 6. 出片
```

第 2 步是最容易被跳过、后果最具体的一步。不装官方 skill，模型会凭「React 常识」写动画——用 `useState` 加 CSS transition，或者用 `setTimeout` 排时间。这种代码在浏览器里看着能动，但在 Remotion 里每一帧都是独立执行的，state 根本不会自己变，渲出来就是一张静止图或者黑屏。有 skill 它才会老老实实用 `interpolate()` 和 `spring()`。

一个上午，六支片子。这在剪辑软件里是不可想象的——不是因为它更快，而是因为它根本不需要「重做」，只需要改参数。

## 🐛 三个只有看画面才发现的 bug

**1. 远山整片变黑，日月光晕消失。**
`interpolateColors` 返回的是 `rgb(r, g, b)`，而我那个旧的颜色辅助函数只认十六进制，于是解析出 `rgba(NaN, NaN, NaN)` —— 浏览器把它当无效色直接丢弃。类型检查 `tsc --noEmit` 全绿，代码逻辑也没错，但画面上就是黑了一大片。这种 bug 你永远不会在「已完成清单」里看到。

**2. 光斑变成脏灰斑。**
46 个柔焦光点用普通混合模式叠在明亮的天空上，暖色半透明叠加会发灰。改成 `screen` 混合之后，只提亮、不发脏。浮尘同理。

**3. 歌词对不齐。**
这支是 Acoustic 版，编曲和速度跟录音室版不同，官方 LRC 的时间**不能直接用**；而 whisper 对唱词的识别质量参差——参数没调之前，前 26 秒整段被 VAD 当静音丢掉，末尾还会复读。最后用的是「官方 LRC 骨架 + whisper 锚点 + 分段线性映射」：骨架给顺序，锚点给真实时间，锚点之间按段插值。

还有两个更细的坑：`TransitionSeries` 的总时长是要扣掉转场重叠的（105 + 120 - 45 = 180 帧），而且转场发生在两段的重叠区——想抽转场中间帧检查，抽错帧号会看到「已经滑完了」。另外中文可变字体别用 `fontWeight`，要用 `fontVariationSettings` 调，否则会触发浏览器的伪粗，糊。

## 🔍 最该说的一件事：AI 的「总结」比它的代码不可信

它交活儿的时候会给你一份很漂亮的清单：

> 完成：天空情绪弧线（清晨→白天→黄昏→暮色→黎明）、9 个手绘场景逐笔绘制、46 个光斑跟随响度呼吸、72 颗浮尘、49 句歌词逐句淡入上浮、全片素材由音频能量驱动……

读起来像完工了。但这些句子描述的是**代码里有什么**，不是**画面里发生了什么**。这两件事经常不是一回事：

- 代码里写「`interpolateColors` 配色映射」——画面里远山是黑的；
- 代码里写「46 个光斑跟着响度呼吸」——画面上是 46 块脏灰斑；
- 代码里写「49 句歌词已写入」——画面里有一句在屏幕上赖了十一秒，因为没人规定它该显示多久。

**这三件事，全部、只在抽出来的静帧里出现。** 文字总结里永远不会出现，因为代码没报错，类型检查全绿，清单也确实「完成」了。

所以我实际的工作流是这样的：AI 写代码 → `npx remotion still` 抽单帧（一张约 45 秒）→ 我把每分钟的帧铺成一张对照表 → 用大白话指「这张不对」→ AI 改代码。

![逐帧核对：每分钟抽一帧铺开](/images/ai-code-video-frames-v2.jpg)

就是这么一张图，把整支片子从「我以为做完了」拉回到「原来这里全是问题」。远山黑不黑、歌词会不会挡脸、场景是不是空得发慌、日出有没有真的升起来——只有铺开看，才轮得到我判断。

> AI 给我的是可编辑的确定性，不是「懂画面」。它理解函数，不理解画面。

这句话反过来也是这次最让我意外的地方：正因为它给出的是**可编辑**的东西，我才能用一句「这段太挤了」让它改，而不是像对着生成式视频那样，重新抽一次卡。AI 把所有东西都变成了可以改的参数——包括我原本根本不会做的美术。

这次体验的一句话总结：**AI 把「制作」变成了「审片」。** 你从拖时间轴的人，变成了验收员和导演。

## 🎞 同一份需求，换个美术就是另一支片子

最离谱的部分在这里。整片所有动画都只是三个数的函数：`rms[f]`（当前帧响度）、`env[f]`（约 0.55 秒的慢包络）、`pulse[f]`（起音脉冲）。这三个数由 `analyze_music.py` 从 mp3 逐帧算出来，写进 `music.json`。

于是——歌词时间轴不变、音频能量不变、分镜帧号不变，只把最上面那层美术换掉，就是完全另一支片子：

![纸箱插画版 · 屋顶的月亮](/images/ai-code-video-box-moon.jpg)

![纸箱插画版 · 日出](/images/ai-code-video-box-sunrise.jpg)

- **手绘暖色版**（`StillApartMV`）· 6875 帧 · 线稿场景、奶油色、胶片颗粒
- **纸箱插画版**（`BoxMV`）· 6875 帧 · 扁平矢量，一个小纸箱站在星球上
- **磁带版**（`TapeMV`）· 1800 帧 / 60 秒 · 录像带质感
- **三支短片**（`S01Wind` / `S02Cat` / `S03Rain`）· 各 300 帧 / 10 秒 · 练「加层 / 加事件 / 加活物」
- **3D 测试**（`S99Spike`）· 60 帧 · Three.js 进 Remotion

同一首歌，五种画风，我一次都没有重排过时间轴。这是代码视频和剪辑软件最本质的差别：**美术可以整体替换，时间轴一动不动。**

## ⚖️ 边界，诚实版

| 能做 | 做不到 / 不建议 |
|---|---|
| 字卡、数据条、UI 演示、logo 动效 | 实拍素材合成 |
| 科普图解、字幕排版、图表动画 | 复杂粒子、真人画面 |
| 地图动画、逐笔手绘、逐字浮现 | 超过 2 分钟的长片（这支 3 分 49 秒已经在硬扛） |
| 3D（配 Three.js）、音频驱动的一切 | 不想读代码就想改细节 |

许可证也要说清楚：Remotion 对个人和 3 人以内公司免费，更大规模商用需要买授权，商用前先确认。

## 💭 最后

以前我以为「不会剪辑」是一道硬门槛：不会拖时间轴、不会调关键帧，就做不出片子。现在门槛换了个位置——变成「能不能一眼看出哪一帧不对」，而这恰恰是 AI 帮不上忙的地方。它会把所有东西做得「看起来完成了」，然后等你去看。

> AI 让「做出来」变得便宜，让「看出来」变得更贵。

如果你也想试：装个 node，`npx create-video@latest` 起个空白工程，然后**别忘**了 `npx skills add remotion-dev/skills`。这两个命令，剩下的交给一个晚上。
