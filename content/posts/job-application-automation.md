<h2>🚀 为什么做这套东西</h2>

<p>秋招季投简历，最烦的不是改简历，而是这些琐事：</p>

<ul>
  <li>每个岗位 JD 不同，简历要反复改，改完还要导出 PDF</li>
  <li>投了哪些公司、投到什么阶段（笔试？一面？二面？），全靠脑子记</li>
  <li>面试完的问题和复盘，过几天就忘</li>
  <li>投了七八家，回头想看看哪家渠道最有效，数据全没有</li>
</ul>

<p>于是做了两件事，组成一个完整的求职自动化闭环：<b>AI 简历流水线</b>（生成定制简历）+ <b>求职追踪看板</b>（管理投递全流程）。</p>

<hr>

<h2>🧩 第一部分：AI 简历流水线</h2>

<h3>1.1 核心工作流</h3>

<blockquote>粘贴职位描述 → AI 评估匹配度 → AI 生成定制简历 + 求职信 → 自动编译 PDF</blockquote>

<p>整个流程跑在本地 Python 脚本里，一条命令搞定：</p>

<pre><code>python run_all.py jobs_input/某公司岗位.txt</code></pre>

<p>脚本会自动完成四步：</p>

<ol>
  <li><b>评估匹配度</b>：AI 读职位描述和我的个人资料，给出 0-10 分的匹配评分，附理由</li>
  <li><b>生成定制简历</b>：根据 JD 关键词调整简历侧重点，用 STAR 法则描述项目经历</li>
  <li><b>生成求职信</b>：针对这家公司单独写一封求职信</li>
  <li><b>编译 PDF</b>：Edge 无头浏览器把 HTML 转成 PDF，直接可投递</li>
</ol>

<h3>1.2 输入方式灵活</h3>

<p>职位描述支持三种输入，TRAE 帮我实现的 <code>job_loader.py</code> 统一处理：</p>

<ul>
  <li>📄 <b>本地文件</b>：<code>jobs_input/xxx.txt</code> 文件路径</li>
  <li>🌐 <b>网页 URL</b>：直接传招聘页面链接，脚本自动抓取正文（纯标准库 HTML 解析，无第三方依赖）</li>
  <li>📋 <b>直接粘贴</b>：命令行里直接传职位描述文本</li>
</ul>

<p>国内招聘平台反爬严重（滑块验证、参数加密），所以不做自动爬站，手动粘贴是最务实的方案。</p>

<h3>1.3 关键设计：个人资料库</h3>

<p>简历内容不是让 AI 凭空生成，而是基于 <code>profile/</code> 目录下的真实资料：</p>

<pre><code>profile/
├── base.md          # 基础信息（姓名/电话/邮箱）
├── education.md     # 教育经历
├── experience.md    # 项目/实习经历
├── skills.md        # 技能清单
├── summary.md       # 个人简介
└── job_objective.md # 求职意向（目标方向/岗位/地点）</code></pre>

<p><b>红线：AI 绝不虚构经历</b>——prompt 里明确要求只基于真实资料做优化表达，不得编造公司、项目、技能。简历造假是零容忍的。</p>

<h3>1.4 技术选型（踩坑总结）</h3>

<table>
  <tr><th>决策点</th><th>选择</th><th>原因</th></tr>
  <tr><td>简历格式</td><td>HTML+CSS</td><td>中文支持好、Windows 免装 2GB 的 LaTeX、设计灵活</td></tr>
  <tr><td>PDF 生成</td><td>Edge headless</td><td>Chrome 在 Windows 上可能静默失败，Edge 稳定</td></tr>
  <tr><td>AI 引擎</td><td>智谱 GLM</td><td>国内直连、免费额度、OpenAI 兼容格式</td></tr>
  <tr><td>HTTP 调用</td><td>纯 urllib</td><td>零第三方依赖，装完 Python 就能跑</td></tr>
  <tr><td>密钥管理</td><td>config_local.py 隔离</td><td>真实密钥不入库，仓库里只有占位符，防泄露</td></tr>
</table>

<p>有个细节：判断 PDF 是否生成成功，不能看命令行输出（Edge 会打印一堆 USB/扩展的无害噪音），要看<b>文件大小是否大于 10KB</b>，这是最可靠的判断标准。</p>

<hr>

<h2>📊 第二部分：求职追踪看板</h2>

<h3>2.1 这是什么</h3>

<p>一个<b>单文件 HTML 应用</b>（零依赖、双击即用、部署即上线），专门管理投递记录的全生命周期。</p>

<h3>2.2 状态流转看板</h3>

<p>完整的状态流：</p>

<blockquote>已投递 → 初筛 → 笔试 → 一面 → 二面 → HR面 → Offer → 已入职 / 未通过</blockquote>

<p>8 列看板，每条记录卡片上点一下按钮就能推进状态，每步自动记录时间线。卡片上直接显示：投递日期、渠道、薪资、标签、下一环节倒计时（面试时间临近会闪烁提醒）、简历文件路径（点击直接打开）。</p>

<h3>2.3 面试复盘库</h3>

<p>每轮面试/笔试都能单独记录：轮次、日期、形式（群面/技术面/HR面）、题目、复盘笔记、结果。标记"未通过"时自动同步记录状态。面试完趁热打铁记下来，这是沉淀经验最快的方式。</p>

<h3>2.4 日历 + 统计</h3>

<ul>
  <li><b>📅 日历视图</b>：月历上每天显示彩色圆点（投递/笔试/面试/Offer/未通过），格子底色深浅表示当天投递密度——一眼看出有没有"海投"或"断档"</li>
  <li><b>📈 统计页</b>：Offer 率、面试率、投递到首面平均天数、渠道分布、薪资区间分布、近 6 个月投递趋势</li>
</ul>

<h3>2.5 数据安全</h3>

<ul>
  <li>数据存在浏览器 localStorage，<b>不上传任何服务器</b>，别人打开页面看到的是空数据</li>
  <li>支持 JSON/CSV 导出备份 + 导入恢复（合并去重 / 替换两种模式）</li>
  <li><b>管理员密码门</b>：部署到公网后，进入前要输密码；还有一键退出按钮，随时清空登录状态</li>
  <li>删除进回收站，可恢复，防手滑</li>
</ul>

<hr>

<h2>🔗 第三部分：闭环打通</h2>

<p>两个工具不是孤立的——TRAE 在流水线里加了一个细节：<code>run_all.py</code> 生成完简历后，会自动把这次投递登记到 <code>jobs_output/投递记录.md</code>：</p>

<pre><code>| 日期 | 公司/岗位 | 匹配分 | 状态 | 备注 |
|------|-----------|--------|------|------|
| 2026-08-30 23:52 | DeepSeek-IDC数据中心团队 | 8/10 | 待投递 | |</code></pre>

<p>于是形成了完整闭环：</p>

<blockquote>AI 评估匹配度 → 生成定制简历 → 自动登记投递 → 追踪笔试面试 → 复盘沉淀 → 统计反哺下一轮投递</blockquote>

<p>匹配分高的岗位优先投，面试复盘反哺简历优化，数据越积越多，决策越来越准。</p>

<h2>💡 总结</h2>

<p>这套流程的核心思路：<b>AI 负责生成，工具负责管理，数据负责反馈</b>。</p>

<ul>
  <li><b>生成</b>：AI 按 JD 定制简历，人只负责审核</li>
  <li><b>管理</b>：状态看板 + 日历 + 复盘，投递进度一目了然</li>
  <li><b>反馈</b>：统计页告诉你哪家渠道有效、平均多久进面试，用数据指导策略</li>
</ul>

<p>全程本地运行、零服务器成本、零第三方依赖，唯一花的就是 GLM 的免费额度。工具是死的，流程是活的——把重复劳动交给自动化，把时间留给真正重要的事。</p>
